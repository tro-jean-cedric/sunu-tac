# TAC-SUNU — Test d'Alignement Culturel

React + FastAPI rebuild of the two self-contained HTML pages of the SUNU Attitude+ (CAP) culture assessment
(originals kept in `legacy/`).

| Part | Path | Who |
|---|---|---|
| Employee test | `/` (`frontend/src/test`) | every employee, LDAP login |
| HR console | `/admin/` (`frontend/src/console`) | DRH Groupe (`HR_ADMIN`) and entity HR (`HR_ENTITY`) |
| API | `/api/` (`backend/`) | FastAPI + PostgreSQL |

The two frontends are separate Vite entries: `npm run build:test` ships only the employee test, `npm run build:console`
only the console, so the HR console is never served to employees unless you deploy it.

## What changed from the HTML version
- **Answers go to the server** (no more JSON files / mailto). The server **re-scores** every submission with a Python port
  of `calcul()` and stores one row per matricule and campaign (re-taking replaces it, as the legacy console did).
- **Identity comes from the directory** (LDAP/AD): matricule = AD `sAMAccountName`, entity = AD `company`. The employee only
  picks *catégorie* and *famille*.
- Drafts are saved on the server (and locally): an employee resumes exactly where they stopped, on any device.
- Groups under 5 respondents are masked **server-side**. Consultations, exports, imports and role changes are audited.
- Legacy pilot data (`.json` files and `TAC1.` codes) can still be imported from the console; if the server is
  unreachable at submission time the test falls back to showing a `TAC1.` code.
- Item bank, scoring and code format are unchanged and **byte-for-byte compatible**: `shared/golden-fixtures.json` was
  produced by running the legacy JavaScript (`shared/generate-golden.cjs`), and both ports are tested against it.

## Layout
```
shared/      referentiel.json (item bank, single source), golden fixtures
backend/     FastAPI app (app/), Alembic migrations, tests
frontend/    Vite + React 18 + TS + @vionhub/design-system (vendored tarball in vendor/)
deploy/      nginx.conf
legacy/      original HTML pages + CA deck
```

## Local development
Prerequisites: Docker. For the non-Docker mode: Node 20+ and [uv](https://docs.astral.sh/uv/).
Everything goes through **`./tac.sh`** (repo root; `./tac.sh help` lists the commands). It creates `.env` from
`.env.example` on first run.

```bash
./tac.sh up --build     # first time: build images, start db + api + web (dev, hot reload), run migrations
./tac.sh restore backups/tac-….dump   # optional: load a copy of an existing TAC database
# http://localhost:8080/ (test)  ·  http://localhost:8080/admin/ (console)  ·  http://localhost:8000/api/docs

./tac.sh up             # later starts
./tac.sh stop           # stop everything (Docker stack and local processes)
```

| Command | What it does |
|---|---|
| `up [--build]` / `build` | Start the dev stack (`docker-compose.override.yml`: sources mounted, uvicorn `--reload`, Vite HMR); `build` rebuilds the images first — needed after a dependency (`uv.lock`, `package-lock.json`) or Dockerfile change |
| `prod` | Production stack (`docker compose -f docker-compose.yml`: nginx static build, no mounts) |
| `stop` / `down` | Stop everything / remove the containers (the database volume is kept) |
| `restart [svc…]` | Restart api + web — applies new Alembic migrations |
| `migrate [--local]` | Apply migrations in the api container (or on the host) |
| `revision "msg"` | New autogenerated Alembic migration |
| `backup [file]` / `restore <file>` | Dump the TAC database (`backups/tac-<date>.dump`, git-ignored) / replace it with a dump — how users, companies and results move between machines |
| `logs [svc…]` · `status` · `psql` | Follow logs (default api web) · containers / processes / API health · psql shell on the Docker DB |
| `reset-db` | Delete the Docker database volume (asks for confirmation) |
| `local` / `local-stop` | API and frontend on the host: starts only the compose `db` container (published on `localhost:15433`), `uv sync`, migrations, then uvicorn `--reload` (:8000) and Vite (http://localhost:5173/, `/admin/`) in the background — logs in `.run/` |
| `test` | Backend pytest + frontend typecheck and vitest |

The Compose project is always named `sunu-tac`, so every checkout (including git worktrees) drives the same
containers and database. The app only talks to its own database: users and companies come from the directory
(LDAP sync) — the initial offline copy is already in the TAC database; carry it with `backup` / `restore`.

Logins in offline mode (`LDAP_ENABLED=false`):
- HR console: `admin.drh` / `ADMIN_PASSWORD` (local account, created at startup with the `HR_ADMIN` role);
- any directory user already in the database: their AD username (e.g. `prenom.nom`) / `DEV_PASSWORD`.

Grant HR roles to real users in **Console → Administration** (DRH Groupe = all entities; DRH Entité = one company).

## Switching on LDAP (from the SUNU network)
1. In `.env`: `LDAP_ENABLED=true`, `LDAP_BIND_DN`, `LDAP_BIND_PASSWORD` (service account), ideally `LDAP_USE_TLS=true`
   or an `ldaps://` URL, and **empty `DEV_PASSWORD`**.
2. Restart the API, then **Console → Administration → Synchroniser l'annuaire** (or set `LDAP_SYNC_CRON_HOUR` for a nightly
   sync). The sync upserts users and companies (normalised names, managers resolved), and never re-activates
   users that HR deactivated.
3. Login now binds against AD with the stored DN, then the UPN, then sAMAccountName — the same order as sunu-achats.

## Read-aloud and Claude AI features
**Read-aloud**: every test step has an *Écouter* button (keyboard **L**), an *auto-read* toggle, a speed
control and a **voice picker** (*Voix* menu, ▶ to preview each voice; the choice is remembered per browser),
and highlights the word being read.
- **Natural voices (recommended)** — set `GOOGLE_TTS_API_KEY` (Google Cloud Text-to-Speech; Chirp 3 HD, Studio,
  Neural2, WaveNet voices) or `AZURE_SPEECH_KEY` + `AZURE_SPEECH_REGION`. Google wins when both are set.
  `TTS_VOICE` sets the default (empty = best French voice). `GET /api/tts/voices` lists the French voices;
  `POST /api/tts` (logged-in users only) returns MP3s cached on disk per voice (`TTS_CACHE_DIR`, a Docker volume
  in compose), so the fixed questions are synthesised once for everyone. Only the text being read is sent.
- **Device voices** — always offered in the picker, and used automatically without a key or if the cloud voice
  fails (best first: Edge "Online (Natural)", Google français, Siri/premium; Apple novelty voices are skipped).

Google key, in short: console.cloud.google.com → create a project → enable **Cloud Text-to-Speech API** → link a
billing account (required even for the free tier) → *APIs & Services → Credentials → Create credentials → API key*
→ restrict it to the Text-to-Speech API → `GOOGLE_TTS_API_KEY=…` in `.env`, restart the API.

**Claude (Anthropic)** — switched on by setting `ANTHROPIC_API_KEY` in `.env` (model: `AI_MODEL`, default
`claude-opus-4-8`). Without a key, every AI element is hidden and the app behaves exactly as before.

| Where | Feature | Endpoint |
|---|---|---|
| Test → results | Streamed personal debrief (cached once per submission), read-aloud | `POST /api/ai/me/debrief` |
| Test → results | "Parlez à votre coach" chat about one's own profile | `POST /api/ai/me/coach` |
| Console → dashboard | **Analyse IA**: structured strengths / risks / gaps / action plan for the active filters (cached per data snapshot) | `POST /api/ai/hr/insights` |
| Console → Assistant IA | Plain-language questions; Claude queries the masked aggregates through tools | `POST /api/ai/hr/ask` |

Guardrails: no AI during the test itself (questions stay word-for-word); Claude never receives names, usernames,
matricules or e-mails — only scores, profiles, catégorie/famille and question text; HR tools reuse the dashboard
summary, so groups under `MIN_GROUP_SIZE` stay masked and no individual record is reachable; chat messages are
capped per user per day (`AI_DAILY_LIMIT`); HR AI calls are written to the audit log. Streaming uses
Server-Sent Events — `deploy/nginx.conf` disables proxy buffering on `/api/ai/`.

## Questionnaire builder (Console → Questionnaires)
The questions and answers are now **versioned data** edited in the console (DRH Groupe; other HR read-only).
`shared/referentiel.json` remains the source of the dimensions, bands, catégories and familles, and seeds
**version 1** (the original bank) at first start; existing campaigns are linked to it.

- **Lifecycle**: draft (editable) → published (frozen) → archived. A campaign uses one *published* version, chosen in
  Campagnes; it can no longer change once answers exist, so every stored result stays interpretable. To evolve a
  questionnaire, create a new version from an existing one (or from the original bank, blank, or a JSON export).
- **Question types**: mises en situation (2–9 reactions with points), choix forcés (3–6 statements of different
  dimensions), pratiques on a configurable 2–9 level scale (reversed items, sub-components), contrôles (social
  desirability / consistency twins), and a 4th **complementary** part with *single choice, multiple choice
  (min/max), yes/no, numeric scale, ranking, free text*, each optionally scored on a dimension and optionally shown
  only after a given answer to an earlier question.
- **Scoring rules** per version: component weights (situations / pratiques / complémentaires; original 0.6 / 0.4),
  validity thresholds (DS, INC, uniform answers, rapid), option shuffling. With the original bank and no scored
  extras, scores and `TAC1.` codes are byte-identical to the legacy HTML (golden tests). Complementary answers travel
  in an optional 5th part of the code, ignored by legacy decoders.
- **Quality**: live server-side validation (errors block publication; warnings for imbalance, checks that can never
  trigger…), coverage matrix per dimension, estimated duration, concurrent-edit protection (revision check).
- **Random draw per respondent** (campaign setting `tirage`): a campaign can ask each employee only N questions per
  category (e.g. 5 situations, 7 blocs, 12 pratiques, 3 contrôles; empty = all), drawn from the bank. Draws are
  balanced across dimensions (round-robin for situations / pratiques, every dimension present in the blocs),
  keep the bank order, and keep a consistency twin only if its paired pratique was drawn; extras are never drawn.
  The draw is seeded by campaign code + matricule: no storage, the same person always gets the same questions
  (draft resume, server re-scoring, `TAC1.` code import). Scores are computed on the questions asked. A draw that
  could leave a dimension unmeasured is refused, and it is locked once the campaign has answers.
- **Item statistics** (published versions): answer distributions, mean score and discrimination index per item,
  hidden under `MIN_GROUP_SIZE` respondents; free-text answers listed shuffled, without identity.
- API: `/api/questionnaires[/{id}[/publish|/archive|/restore|/export|/stats]]`, `POST /api/questionnaires/validate`,
  `GET /api/campaigns/{id}/questionnaire` (test app). All changes are audited.

```bash
cd backend && uv run pytest          # scoring/codec parity with legacy + API (auth, scoping, n<5, import, CSV)

cd frontend && npm run typecheck
```

## Deployment (intranet)
```bash
cp .env.example .env    # set JWT_SECRET, ADMIN_PASSWORD, LDAP_*, COOKIE_SECURE=true behind HTTPS
# -f docker-compose.yml skips docker-compose.override.yml (dev hot reload) — always pass it on a server
docker compose -f docker-compose.yml up -d --build   # db + api + nginx on :8080
# users: Console → Administration → Synchroniser l'annuaire (LDAP), or load a copy made with ./tac.sh backup:
docker compose -f docker-compose.yml exec -T db pg_restore -U tac -d tac --clean --if-exists --no-owner < tac.dump
```
`deploy/nginx.conf` serves the test at `/`, the console at `/admin/` (old `/test/` and `/console/` links redirect) and proxies `/api/`. To publish the test without the console, build the
web image with `--build-arg BUILD_MODE=test-only`, and restrict `/admin/` to the HR network.

## Points of vigilance (from the deployment guide)
- Responses are personal data: declare the processing (ARTCI, CDP…) and present it to staff representatives first.
- Interpretation thresholds (`bandes` in `shared/referentiel.json`) are provisional until the pilot validation.
- Icons are fetched from the Iconify CDN at runtime; on an air-gapped intranet, bundle them (see design-system host-setup § 5).
